# DirectAI Campaign Audit v2.0

## Что делает

Разбирает одну кампанию Яндекс Директа и выдаёт проверяемый план улучшений.
Ничего не меняет: только `run_read` и локальные файлы.

Главный принцип: **сначала данные, потом выводы**. Все цифры в отчётах берутся
из одного `audit.json`, который собирается скриптами из сырых ответов MCP.

## Жёсткие запреты

- Никаких `plan_write`, `apply_write`, `campaigns_update`, `negatives_set`,
  `ads_update`, `bid_modifiers_set` и любых других действий записи.
- Не менять бюджеты, ставки, стратегии, цели и минус-фразы.
- Не выдавать оценку экономии за гарантию.
- Не подставлять ноль вместо отсутствующих данных.
- Не придумывать действия, поля и идентификаторы.
- Не писать в журнал предложения агента как решения пользователя.

## Конвейер

```
1. Агент: search_actions → describe_action → run_read (output=file, format=json)
2. Агент: складывает ответы в <session>/raw/ и описывает их в session.json
3. build_audit.py <session>      → audit.json  (нормализация + правила + валидация)
4. validate_audit.py audit.json  → PASS / WARN / FAIL
5. render_md.py / render_xlsx.py / render_html.py — из того же audit.json
6. journal_append.py — только решения пользователя
```

Скрипты не ходят в сеть и не вызывают MCP. Агент не переписывает цифры вручную.

## Порядок работы

1. **Режим.** По умолчанию `deep`. Режимы: `quick`, `deep`, `semantic`, `rsy`,
   `funnel`, `growth`, `monitor`, `experiment`; комбинации через `+`
   (`deep+semantic`). Что доступно при каких данных — `references/modes.md`.
2. **Периоды.** По умолчанию два завершённых периода по 14 дней, сегодняшний
   день исключён. Другие горизонты: 7, 28, 90 дней или свои даты.
3. **Чтение.** Для каждого действия сначала `describe_action`, потом `run_read`
   с `output=file`, `format=json`. Реестр действий, аргументы и ограничения —
   `references/tool-contract.md`. Обязательный минимум: `stats_compare`,
   `campaigns_get`.
4. **Сохранение.** Ответы кладутся в `raw/`, источники описываются в
   `session.json` (файл, действие, параметры, статус, пагинация, предупреждения).
5. **Сборка.** `python scripts/build_audit.py <session> -o audit.json`.
6. **Валидация.** `python scripts/validate_audit.py audit.json`. При `FAIL`
   публиковать подтверждённый отчёт нельзя — только диагностический
   (`--diagnostic`).
7. **Отчёты.** Markdown обязателен; Excel и HTML — из того же JSON.
8. **Итог в чат.** 3–5 главных выводов, приоритеты, путь к файлам, вопрос
   «какой пункт разбираем».

## Что проверяется

Полный список с порогами — `references/checklist.md`. Кратко:

- отслеживание: счётчик, основная цель, клики против визитов;
- модерация и расширения объявлений;
- динамика конверсий, CPA, CTR с проверкой достаточности данных;
- поисковые запросы: интенты, мусор, кандидаты в минус-фразы с проверкой
  конфликтов;
- площадки РСЯ: порог `2 × CPA` — только ориентир внимания, не основание
  для исключения;
- устройства и регионы: сегментный CPA только при доказанной сопоставимости;
- история изменений: последовательность событий, не причинность;
- экономика воронки — только при подтверждённой выручке.

## Формулы

`Δ = A − B`, `Δ% = (A − B) / B × 100`, для долей дополнительно `п.п. = A − B`.
При `B = 0` относительное изменение не считается. Подробно —
`references/metrics-contract.md`.

## Файлы сессии

```
<session>/
├── session.json     # задание: кабинет, кампания, режимы, периоды, пороги, продукт
├── raw/             # ответы run_read как есть (JSON-конверт {meta, rows})
└── audit.json       # результат сборки
```

`session.json` — единственный файл, который пишет агент. Пример —
`examples/example-87654321/session.json`.

## Отчёты

- `audit.md` — 10 разделов, читается человеком.
- `audit.xlsx` — 9 листов, числа числами, ID текстом, автофильтры.
- `audit.html` — автономный файл, фильтры по приоритетам, вкладки сегментов.

Каталог `reports/` и `raw/` исключены из Git (`.gitignore`).

## Восстановление и тесты

- Резервная копия до v2.0 хранится вне репозитория (манифест с SHA-256 внутри).
- Тесты: `python -m unittest discover -s tests -p "test_*.py"` — 183 проверки,
  30 обязательных сценариев, офлайн, без реальных данных.

## Ограничения, о которых нужно говорить

- `ExcludedSites` не читается через `campaigns_get`: автоматическая замена
  списка площадок небезопасна, поэтому исключение площадок — ручное действие.
- Методы Reports API имеют лимит (ошибка 56): пустой ответ при такой ошибке
  не доказывает отсутствие данных.
- Задержка конверсий по умолчанию неизвестна: свежие периоды помечаются как
  незрелые.
- Прибыль и ДРР считаются только по выручке, которую дал пользователь.
- Морфология минус-фраз проверяется приблизительно (без словаря): совпадение
  по основе помечается и требует проверки в прогнозе Директа.
