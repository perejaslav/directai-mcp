# Качество данных

Проверки выполняются до аналитики. Реализация: `scripts/auditlib/dq.py`.
Состояния: `passed`, `warning`, `blocked`, `unavailable`, `not_applicable`.

`unavailable` **не** равно «проверено и всё хорошо». Если данных нет, это
фиксируется и блокирует соответствующие выводы.

## Гейты

| Гейт | Что блокирует | Когда включается |
|---|---|---|
| `all` | весь аудит | кампания или кабинет не идентифицированы, принадлежность источника не доказана |
| `identity` | анализ настроек | нет `campaigns_get` |
| `dynamics` | выводы о динамике | нет A/B, B пуст, периоды несопоставимы, свежий период |
| `cpa` | всё, что опирается на CPA | нет конверсий, нет основной цели, атрибуция расходится |
| `segments` | сегментный анализ | лимит API, усечение, несопоставимость |
| `semantic` | работа с запросами | нет `stats_search_queries` |
| `rsy` | площадки | нет `stats_placements` |
| `funnel` | воронка | нет Метрики |
| `growth` | рост | нет сегментов с конверсиями |
| `history` | история | нет журнала и `changes_check` |

## Критические и раздельные блокировки

`blocked` бывает двух уровней.

**Критические** — подтверждённый отчёт невозможен, валидатор возвращает `FAIL`:

- `DQ-ACC-01`, `DQ-ACC-02` — кабинет не подтверждён;
- `DQ-CMP-01` — кампания не подтверждена;
- `DQ-SRC-02` — нет настроек кампании;
- `DQ-NEG-01` — отрицательные значения в деньгах;
- `DQ-UNI-01` — валюта не рубль;
- любая проверка с гейтом `all`.

**Раздельные** — валидатор возвращает `WARN`, а в отчёте ограничивается
соответствующий раздел:

- `DQ-API-01` — лимит API: без площадок, запросов и сегментов;
- `DQ-MET-01/02` — нет трафика: без динамики и CPA;
- `DQ-PRD-01/03` — периоды: без динамики;
- `DQ-PAG-01/02` — неполная выгрузка: без сегментных рекомендаций.

Статус `blocked` без единой блокирующей проверки — это `FAIL` (несогласованность),
как и `passed` при наличии предупреждений.

## Ловушки, проверенные на живом API

1. **Ошибка 56 = лимит запросов, а не пустая кампания.**
   `stats_placements` может вернуть `0 строк` и в шапке
   `⚠ Direct API error 56`. Это `blocked`, а не «площадок нет».
2. **`0 строк` без ошибки** — тоже не доказательство отсутствия: срез мог быть
   не применён или кампания не работала в этом размещении.
3. **Период в шапке** может быть только началом (`A: 09.10.2026, B: 25.09.2026`).
   Проверяются доступные части, полное совпадение не выдумывается.
4. **`campaigns_get` не отдаёт `ExcludedSites`.** Список площадок читается
   только в интерфейсе.
5. **`campaign_journal` всегда Markdown**, даже при `format=json`.

## Правила разбора

- числа приходят строками с пробелами: `"326 064"`, `"103 549.40"`;
- `"—"` → `None`, `"0"` → `0`;
- проценты и п.п. различаются по суффиксу;
- если колонка сегмента не найдена — сегмент `unavailable` со списком
  полученных колонок, без подстановки нулей;
- `meta.action` в файле должен совпадать с объявленным действием;
- SHA-256 каждого файла фиксируется в `data_sources`.

## Что делать при `blocked`

1. Если блокировка критическая — не публиковать подтверждённый отчёт.
2. Если раздельная — опубликовать можно, но с явным ограничением раздела.
3. Показать, какие выводы недоступны и почему.
4. Перечитать данные (с паузой при лимите) или запросить недостающий срез.
5. После устранения — пересобрать `audit.json` с нуля, не править его руками.

## Неполная выгрузка

`truncated: true` или `pagination_complete: false` означают, что часть строк
могла не прийти. В этом случае:

- сегментные рекомендации не формируются (площадки, запросы, фразы, устройства, регионы);
- выводы по объявлениям не формируются, если усечён `ads_list`;
- в отчёте остаётся ограничение с причиной.

Лучше показать меньше выводов, чем построить исключение площадки по половине строк.
