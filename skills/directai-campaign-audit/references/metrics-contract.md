# Контракт показателей

Правила, по которым считаются и сравниваются все числа аудита.
Реализация: `scripts/auditlib/metrics.py`.

## 1. База сравнения

`A` — свежий период, `B` — предыдущий.

```
Δ  = A − B
Δ% = (A − B) / B × 100
п.п. = A − B        (только для долей: CTR, CR, отказы)
```

Пример: CTR был 4%, стал 5%.
Это `+1 п.п.` и `+25%` одновременно — два разных показателя, оба нужны.

Правила:

- при `B = 0` относительное изменение **не вычисляется**: «нет базы для сравнения».
  Бесконечность, ноль и «+100%» не подставляются;
- отрицательные изменения сохраняют знак: падение всегда `−`;
- округление — только для отображения. Расчёт идёт на сырых значениях;
- если изменение есть, но после округления числа выглядят одинаково,
  ставится флаг `display_hides_change` и пояснение в отчёте.

## 2. Почему не используются Δ из `stats_compare`

Проверено на живом ответе DirectAI v1.17.2:

| Метрика | A | B | Δ инструмента | Правильно |
|---|---|---|---|---|
| Показы | 326 064 | 257 550 | −68 514 | −68 514 ✓ |
| CTR, % | 0.36 | 0.43 | +0.07 п.п. | −0.07 п.п. ✗ знак |
| Конверсии | 3 | 4 | +1 | −1 ✗ знак |
| CPA, ₽ | 34 516.47 | 25 121.21 | −27.22% | +37.4% ✗ база |

`Δ%` инструмента делится на **A**, а не на B; у части метрик знак перевёрнут.
Поэтому `build_audit.py` всегда пересчитывает изменения из A и B.

## 3. Источники CPA

Хранятся раздельно, не смешиваются:

| Вид | Источник | Когда используется |
|---|---|---|
| Фактический CPA кампании | `stats_compare`, период A | основная оценка |
| Исторический CPA | `stats_compare`, период B | база для динамики |
| Целевой CPA | `session.thresholds.target_cpa_rub` | если задан пользователем |
| CPA сегмента | `stats_devices` / `stats_regions` / `stats_placements` | только при доказанной сопоставимости |

Общий CPA — всегда из `stats_compare`. Сегментный CPA — из источника сегмента,
и только если:

1. сумма расхода сегментов совпадает с расходом кампании в пределах допуска
   (`tolerance_segment_sum`, по умолчанию 5%);
2. основная цель задана;
3. период и атрибуция те же (проверяется по шапке источника).

Если условие не выполнено — вывод «сравнение недоступно» (`SEG-00`), а не
сравнение чисел из разных периодов.

## 4. Порог `2 × CPA`

Это **диагностический ориентир внимания**, а не критерий исключения.

- расход объекта ≥ порога и 0 конверсий → `RSY-01`, кандидат на разбор;
- расход ниже порога и 0 конверсий → `RSY-02`, только наблюдение;
- исключение предлагается лишь при подтверждённой проблеме и с условиями.

Регрессия: CPA 1 460 ₽, порог 2 920 ₽, расход площадки 2 700 ₽ → `RSY-02`.
Площадка **не** попадает в рекомендации на исключение и в расход под риском.

## 5. Нули, пропуски, бесконечности

- `null` / `—` → `None`, в отчёте «нет данных»;
- `0` → `0`, это факт;
- CPA при 0 конверсий → `None`, не бесконечность;
- деление на ноль → `None` + пояснение;
- NaN и Infinity отбрасываются при разборе и ловятся валидатором.

## 6. Достаточность данных

Порог по умолчанию: 1 000 показов, 100 кликов, 10 конверсий на период.
Значения настраиваются в `session.thresholds`.

- мало данных → «недостаточно статистики», вывод не делается (`STAT-01`);
- для долей (CTR, CR) — z-тест двух долей, только если `np ≥ 5` в обоих
  периодах; иначе тест не считается;
- для счётчиков конверсий — интервал отношения частот (Katz, лог-шкала),
  помечается как приближение;
- при множественных сравнениях сегментов применяется поправка Бонферрони:
  `alpha / число проверок`, и это указывается в ограничениях.

Никаких «доверительных интервалов на глаз»: если предпосылки не выполнены,
инструмент возвращает `valid=false` и причину.

## 7. Задержка конверсий

- если `session.thresholds.conversion_delay_days` задан — используется он;
- если нет и период закрыт менее 3 дней назад — предупреждение `DQ-DLY-01`
  и блокировка выводов о динамике;
- универсальное значение задержки не подставляется.

## 8. Единицы

| Показатель | Единица | Формат |
|---|---|---|
| расход, CPC, CPA | рубли с НДС | `#,##0.00 ₽` |
| CTR, CR, отказы | проценты | `#,##0.00"%"` |
| изменение долей | процентные пункты | `+0.07 п.п.` |
| показы, клики, конверсии | штуки | целое |

Если в шапке источника валюта не рубль — `DQ-UNI-01` блокирует денежные выводы.

## 9. Экономика

- ДРР = расход / подтверждённая выручка × 100;
- ROAS = выручка / расход;
- прибыль считается только при наличии себестоимости и выручки;
- CPA не равен стоимости клиента, заявка не равна продаже;
- выручка берётся только из данных пользователя (`session.economics`),
  не оценивается по CPA.
