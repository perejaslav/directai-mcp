# Режимы аудита

Реализация: `MODE_SCOPES` в `scripts/auditlib/rules.py`,
доступность — `mode_status` в `audit.json`.

| Режим | Назначение | Обязательные данные | Деградация |
|---|---|---|---|
| `quick` | 5 главных проблем | `stats_compare`, `campaigns_get` | отчёт короче, глубокие блоки не запускаются |
| `deep` | все доступные блоки | те же + любые сегменты | помечает `degraded`, если часть блоков недоступна |
| `semantic` | запросы, фразы, автотаргетинг, минусы | `stats_search_queries`, `keywords_list`, `negatives_audit` | без контекста продукта минус-фразы не предлагаются |
| `rsy` | площадки, креативы, сегменты | `stats_placements` + работа в сетях | недоступен для чисто поисковой кампании |
| `funnel` | от клика до продажи | `metrika_direct_cpa` + выручка | без выручки ДРР и прибыль не считаются |
| `growth` | возможности расширения | `stats_adgroups`, конверсии | список может быть пустым — это нормально |
| `monitor` | сравнение с прошлым аудитом | предыдущий `audit.json` | без снимка режим недоступен |
| `experiment` | проверяемые гипотезы | находки с низкой уверенностью | без гипотез режим недоступен |

## Комбинации

Режимы складываются: `deep+semantic`, `rsy+funnel`, `quick+growth`.
Итоговый набор блоков — объединение; в `mode` записывается список.

## Что делает каждый блок

### quick

Только `core`: отслеживание, модерация, динамика, деньги. Годится для
ежедневной проверки «всё ли живо».

### deep

`core + semantic + rsy + funnel + growth + history`. Если часть источников
недоступна, в `mode_status.deep` появляется `degraded: true` и перечень
отсутствующих действий. Отчёт всё равно строится.

### semantic

- классификация запросов по 7 классам;
- поиск запросов без конверсий;
- кандидаты в минус-фразы с проверкой блокировки и конфликтов;
- дубли и пересечения фраз;
- гигиена существующих минус-фраз (в том числе «минус игнорируется»).

Информационный запрос не считается мусором автоматически: он может быть
частью пути к заявке. Без описания продукта (`session.product.what`)
минус-фразы не предлагаются.

### rsy

- площадки: расход, клики, CTR, конверсии, CPA;
- порог `2 × CPA` как ориентир внимания;
- аномальный CTR при достаточном числе кликов — гипотеза о качестве трафика;
- исключение площадки — только вручную и с условиями.

Частотный анализ креативов недоступен: в API нет частоты показов на
пользователя. Это фиксируется как ограничение, а не имитируется.

### funnel

`Показы → Клики → Визиты → Заявки → Квалифицированные лиды → Продажи`.

Считаются только доступные этапы. CRM и 1С подключаются лишь через
разрешённые источники или выгрузки пользователя. Прибыль без себестоимости
и выручки не выводится.

### growth

- эффективные группы и запросы (CPA ниже среднего при достаточных конверсиях);
- перспективные направления;
- улучшения объявлений.

Формулировка «даст +N заявок» запрещена: прогноз без модели — обещание.

### monitor

Сравнивает два реально существующих `audit.json`: метрики, новые и закрытые
правила, добавленные и снятые рекомендации. Перед сравнением сверяются кабинет,
кампания, основная цель и атрибуция. Если снимка нет или он несовместим —
режим недоступен, а не «всё хорошо».

### experiment

Для каждой гипотезы: метрика, базовая линия, условия старта и остановки,
минимальная длительность, порог объёма, критерии успеха и неуспеха.
Бюджеты не меняются.

## Автоматических проверок по расписанию нет

Навык не создаёт постоянных заданий. Регулярный запуск — только по отдельной
просьбе пользователя.
