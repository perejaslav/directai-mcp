# Checklist аудита кампании

Каждая проверка: порог → что сказать пользователю → инструмент записи для плана
(план НЕ выполнять из аудита). N — параметр, default 2×CPA цели
(CPA по основной цели; если конверсий нет — сказать об этом прямо).
CPA/конверсии для N и всего отчёта — только из `stats_compare`;
срезы — лишь доли/распределение, с пометкой.

## 1. Мусорные поисковые запросы

- Порог: запрос с расходом > 0 и 0 конверсий, явно мимо услуги
  (`stats_search_queries` + `negatives_audit`).
- Сказать: «Запрос „X“ потратил N ₽ без заявок — предлагаю в минус».
- В план: `negatives_set` (минусы add).

## 2. Фразы/группы с расходом без конверсий

- Порог: расход ≥ N (default 2×CPA цели) и 0 конверсий
  (`stats_keywords`, `stats_adgroups`).
- Сказать: «Фраза/группа X потратила N ₽ (≥ 2×CPA) без заявок —
  кандидат на паузу/переработку».
- В план: `keywords_state` (пауза фразы), `adgroups_update` — только для
  тестовых `[TEST DirectAI]`; в боевой — предложить переработку текстов/ставок.

## 3. Площадки РСЯ с расходом без конверсий

- Порог: площадка с расходом ≥ N и 0 конверсий (`stats_placements`,
  только если есть показы в сетях).
- Сказать: «Площадка X съела N ₽ без заявок — кандидат в запрещённые».
- В план: запрещённые площадки (ExcludedSites add).

## 4. Объявления без расширений

- Порог: объявление без быстрых ссылок / уточнений / изображения /
  DisplayUrlPath (`extensions_list`, `ads_list`).
- Сказать: «В объявлении X нет {быстрых ссылок/уточнений/картинки/
  отображаемой ссылки} — дописать».
- В план: `extensions_create`, `ads_update` (DisplayUrlPath проверить в read-back,
  длины — по лимитам Директа до prepare).

## 5. Модерация

- Порог: любое отклонённое объявление/фраза (`moderation_check`).
- Сказать: «X отклонено: причина — Y».
- В план: `ads_update` / `keywords_update` после правки текстов.

## 6. Счётчик и основная цель

- Порог: счётчик/основная цель не заданы или цель не та
  (`counter_check`, `campaigns_get`, блок `goal {id, label, source}`).
- Сказать: «Счётчик X / цель Y: {не привязан / не та цель} —
  стратегия оптимизируется не на то».
- В план: цель правится в интерфейсе/Метрике (не через MCP-запись);
  бюджеты и смену стратегии не предлагать.

## 7. Просадка/рост > 20%

- Порог: изменение метрики в `stats_compare` > 20%.
- Δ всегда = A−B (свежий минус прошлый: рост +, падение −). Если инструмент
  отдал B−A — перевернуть знаки Δ/Δ% в отчёте и подписать формулу под таблицей.
- Репрезентативность прошлого периода — по данным (есть ли показы/расход
  по дням), а не по StartDate кампании. Если трафик в прошлом периоде был —
  сравнение валидно.
- Сказать главную причину одним из четырёх: показы, CTR, цена клика, конверсия
  (CR/CPA по основной цели). Пример: «Заявки упали на 35%: показы те же,
  CTR тот же, конверсия упала вдвое — дело в сайте/спросе, не в ставках».
- В план: ничего не выполнять без подтверждения; сравнение — только `stats_compare`.

## 8. Устройства/регионы с CPA > 2× среднего

- Порог: CPA сегмента > 2× среднего CPA кампании
  (`stats_devices`, `stats_regions`).
- Сказать: «На {мобильных/десктопе, регион X} CPA N ₽ — вдвое выше среднего.
  Предлагаю корректировку».
- В план: `bid_modifiers_set` (только предложить, не выполнять).
