# DirectAI Connection Doctor

## Goal

Агент по шагам диагностирует, почему Direct AI MCP не работает, и выдаёт
пользователю ОДИН готовый блок PowerShell под найденную проблему.
Диагностика read-only: никаких kill/install/правок конфига без явного «да»
пользователя; по умолчанию — выдать команды блоком.

## Порядок работы

1. Запустить `directai-mcp doctor --json` (без сети — с `--skip-api`).
2. Разобрать JSON: поле `overall` (`ok`/`warn`/`fail`), массив `checks`
   (id a–i, `status` OK/WARN/FAIL, `detail`, `hint`).
3. Найти первую проверку со статусом FAIL, иначе первую с WARN.
4. Открыть `references/playbooks.md`, взять рецепт под эту проверку.
5. Выдать пользователю ОДИН готовый блок PowerShell целиком.
6. Дождаться результата, дальше — по новому выводу doctor.
7. Перед переустановкой — строгая проверка `doctor --preinstall`
   (c → WARN, d → FAIL); в обычном режиме занятый exe — INFO, не тревога.

## Правила

- Бюджеты кампаний не трогать; write-действия Директа в этом скилле запрещены.
- Токены никогда не печатать и не просить в чат (только «есть/нет/длина»).
- Guard не выключать, конфиг guard не искать и не править.
- Блокировка guard — защита, а не ошибка (см. README §6.1).
- Фильтр по `python.exe … gateway run` не использовать: Hermes запущен
  отдельным процессом (direct spawn) и таким фильтром не ловится.
- Если doctor не запускается вовсе (exe сломан) — fallback-проверки вручную:
  `(Get-Command directai-mcp).Source`, список процессов, наличие
  `%USERPROFILE%\.directai\accounts.toml` — тоже одним блоком.

## Коды Direct API (кратко, полные рецепты — в playbooks)

| Код | Смысл | Действие |
|---|---|---|
| 53 | неверный токен | `set-token`, затем `check` |
| 58 | нет доступа к API | заявка в интерфейсе Директа |
| 513 | логин не подключён | проверить Client-Login |
| 152 | кончились баллы | ждать сброса лимита |
| 52 / 506 / 1000 / 1020 | сеть/сервис | повторить позже |
