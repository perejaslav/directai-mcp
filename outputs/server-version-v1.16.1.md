## 1. Что сделано

### 1.1 Статус версий — `describe_action` без имени

`describe_action` теперь принимает `name` как необязательный: без имени (или
с пустой строкой) возвращается блок статуса, вызов не тратит API.

```
DirectAI MCP: статус сервера (без вызова API).
server_version (пакет, importlib.metadata): 1.15.1
code_version (код, запущенный в этом процессе): 1.16.1
disk_version (исходники на диске): 1.16.1

⚠ Метаданные установленного пакета: v1.15.1, а код сервера: v1.16.1 —
переустановите пакет (uv tool install --force --editable .), перезапуск
сервера не поможет.

Как читать: …
Параметры и пример действия: describe_action('<имя_действия>'); список имён:
search_actions('').
```

С `name` поведение прежнее (параметры, пример, ограничения) — правок в
существующих ответах нет.

### 1.2 Три числа вместо одного — и почему

По заданию `server_version` берётся из пакета (`importlib.metadata`), а не из
файлов на диске. На практике этого одного числа мало: у **editable**-установки
метаданные (`*.dist-info`) обновляются только переустановкой, поэтому после
любого `git pull` с новой версией они отстают от кода. Проверено на этой
машине: `importlib.metadata.version("directai-mcp")` → `1.15.1`, при этом
код в памяти процесса и на диске — `1.16.1` (и ранее `1.16.0`), а
`directai-mcp probe` отдаёт `version=1.16.0`.

Поэтому блок показывает три версии и различает два расхождения, потому что
лечатся они по-разному:

| Расхождение | Что это значит | Что делать |
|---|---|---|
| `code_version` ≠ `disk_version` | процесс запущен на старом коде | **перезапустить MCP-сервер** |
| `server_version` ≠ `code_version` | метаданные установки отстали | **переустановить пакет** (`uv tool install --force --editable .`, README §7) |

Если бы `server_version` был единственным числом, агент увидел бы «1.15.1»
у сервера, который на самом деле выполняет 1.16.x, и предложил бы бесполезный
перезапуск. Предупреждение «перезапустите MCP-сервер» в задании закрывает
первый случай; второй добавлен, иначе подсказка была бы неверной по существу.

Неизвестные значения не выдумываются: если метаданных нет
(`PackageNotFoundError`) — `server_version: —`, без предупреждения.

## 2. Issue #2 — тесты с зашитой датой

Причина падения была не в коде: фикстура кеша задавала
`updated_at = "2026-09-26T10:00:00+03:00"`, а `ensure_cache` освежает кеш при
`cache_age_days > CACHE_STALE_DAYS` (`CACHE_STALE_DAYS = 7`), поэтому с
03.10.2026 четыре теста начинали делать незваный `Clients.get` и падать на
`respx` (`assert_all_mocked`) вместо содержательного падения.

Фикс (`tests/test_v11_step2.py`):

- добавлен хелпер `_ago(**delta)` — метка времени относительно «сейчас»;
- свежий кеш в фикстуре по умолчанию — `_ago(hours=1)`;
- намеренно устаревший кеш в `test_stale_cache_refreshes` —
  `_ago(days=CACHE_STALE_DAYS + 2)`, порог берётся из конфига, а не из
  воздуха;
- `tests/test_v11_step2.py`: **11 passed** (было 7 passed / 4 failed).

Проверено, что «свежесть» теста не привязана к календарю: тесты с
`CACHE_STALE_DAYS = 7` теперь не сломаются ни через неделю, ни через год.
Другие файлы с зашитыми датами не трогались: в `tests/test_v11_step4.py`
та же дата есть, но тест проверяет саму строку `updated_at` и не зависит от
её возраста (это отдельная чистка, не входила в задачу).

## 3. Тесты и проверки

Новый файл `tests/test_v1161_server_version.py` (9 тестов):

- в ответе есть все три версии, `code_version` совпадает с `__version__`;
- `server_version` приходит именно из `importlib.metadata` (подмена
  `importlib.metadata.version` видна в выводе) и ищется **один** раз за вызов
  (`importlib.metadata` сканирует `sys.path` на каждый `version`, поэтому
  предупреждения получают версии аргументами, а не перечитывают их);
- расхождение с диском → «перезапустите MCP-сервер» и **не** «переустановите
  пакет» (совпадение предупреждения с причиной);
- совпадение всех трёх → ни одного предупреждения;
- `PackageNotFoundError` → «—» без предупреждения;
- чистая функция `server_version_warnings(code, disk, meta)` и пустые
  неизвестные версии не дают ложных предупреждений;
- `describe_action('<имя>')` работает как раньше; пустая строка — статус, а не
  ошибка.

Общий прогон: `ruff check src tests` — чисто; `pytest` — **736 passed,
0 failed** (до правок было 723 passed / 4 failed).
