# AGENTS.md — протокол установки и диагностики DirectAI MCP

Ты — ИИ-агент, которому дали только ссылку на этот репозиторий. Человек
не знает git, uv и PowerShell: объясняй простыми словами, одно действие
за раз, каждую команду давай отдельно и жди результата.

## −1. Проверь ОС — сначала, до всего остального

Не Windows — сообщи человеку, что инструкции только для Windows 11
(PowerShell), macOS/Linux не тестировались и не поддерживаются.
Дальше не устанавливай без его явного решения: жди, что он скажет.

## 0. Не можешь открыть URL — клонируй и читай локально

Не открылась ссылка на репозиторий или файл — не гадай по памяти:
склонируй репозиторий и читай файлы локально. Клон — в постоянный
каталог, не в temp:

```powershell
cd $env:USERPROFILE
git clone https://github.com/perejaslav/directai-mcp.git directai-mcp
cd $env:USERPROFILE\directai-mcp
```

Папка `directai-mcp` уже есть — не клонируй, а выполни `git pull` внутри неё.
Полная инструкция для новичка — `README.md §1.1` (выполняй по шагам).

## 1. Токен — БЛОКИРУЮЩИЙ шаг, делает только человек

Токен в чат писать ЗАПРЕЩЕНО. Человек САМ выполняет в своём терминале
`directai-mcp set-token --login ЕГО_ЛОГИН` и вводит токен в скрытое поле.
Агент ждёт и ничего не вводит сам. Если человек вставил токен в чат —
останови работу, попроси отозвать токен в Яндекс ID и выпустить новый.
Подробности — `README.md §1.1`, шаги 5–6.

## 2. Никогда не делай cd внутрь uv tool dir

Каталог установки (`uv tool dir`) — служебный: не делай туда `cd`,
не клади туда копии и бэкапы (копии внутри tool dir `uv` считает
инструментами и выдаёт `malformed`). Рабочий каталог для команд —
`$env:USERPROFILE` или корень репозитория. Перед
`uv tool install --force` — сначала бэкап ВНЕ tool dir (например
`$env:USERPROFILE\directai-mcp-tool-backup-<дата>`).

Путь к exe для конфигов харнесов — стабильный лаунчер:

```powershell
(Get-Command directai-mcp).Source
```

(обычно `%USERPROFILE%\.local\bin\directai-mcp.exe`). Указывай в
конфигах именно его — не путь внутрь tool dir.

## 3. «Ignoring malformed tool» — не сноси рабочий инструмент

Строка `warning: Ignoring malformed tool ... (run uv tool uninstall ...)`
означает битую копию/рецепт, а не повод удалять рабочий `directai-mcp`.
Порядок: попроси человека закрыть ВСЕ окна харнесов, затем переустанови
поверх с `--force` (бэкап — см. §2). `uninstall` — только для заведомо
мусорных записей (бэкапов), рабочий инструмент не трогай.

## 4. os error 32 — файл держат другие MCP-клиенты

`os error 32` при переустановке: exe занят запущенными MCP-клиентами
(харнесы, в т.ч. висящие `opencode serve`). Покажи владельцев:

```powershell
Get-CimInstance Win32_Process -Filter 'Name="directai-mcp.exe"' |
  Select-Object ProcessId, ParentProcessId, CommandLine
```

Важно: шлюз Hermes (`python.exe … hermes_cli.main … gateway run`)
работает в фоне и держит `directai-mcp.exe` даже при закрытых окнах
харнесов. Поэтому перед переустановкой человек САМ останавливает
сервер и шлюз, затем запускает Hermes заново:

```powershell
Get-Process directai-mcp -ErrorAction SilentlyContinue | Stop-Process
Get-CimInstance Win32_Process -Filter 'Name="python.exe"' |
  Where-Object { $_.CommandLine -like '*hermes_cli.main*gateway run*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId }
```

Чужие процессы агент не убивает — команды выполняет человек.
Сам агент, работающий внутри харнеса, переустановку при живых
харнесах не выполняет — готовит блок команд, человек запускает
его сам в обычном PowerShell при закрытых харнесах и остановленном
шлюзе (после установки Hermes запускается заново).

## 5. Проверка — только по цепочке, сырые stdio-пробы запрещены

Порядок проверки, без пропусков:

1. `directai-mcp --version` — версия совпадает с репозиторием;
2. `directai-mcp check` — строки `OK` по каждому аккаунту;
3. `directai-mcp probe` — `OK server=...`, инструмент `stats_summary` найден
   (самопроверка через настоящий MCP-клиент: initialize → tools/list →
   search_actions; Reports API не трогает, баллы не тратятся);
4. регистрация в харнесе (готовые блоки — `examples/harness-configs.md`;
   для Hermes — неинтерактивно, см. тот же файл);
5. `hermes mcp test <имя>` (для Hermes) — но помни: тест соединения
   ≠ доступность в сессии;
6. `/reload-mcp` или новая сессия (человек перезапускает сам);
7. реальный запрос в новой сессии («Используй только directai-mcp:
   покажи расходы по всем аккаунтам за вчера») и сверка цифр
   с веб-интерфейсом Директа.

Сырые stdio-пробы вручную (echo JSON в stdin процесса) не делать —
только команда `probe`.

## 6. Чужой MCP отключать — только последним шагом и только по просьбе

Отключать другой MCP-сервер (например, LidFly) — только если человек
прямо попросил, и только после того, как всё остальное проверено.
По умолчанию чужие MCP не трогай (не выключай, не удаляй, не правишь
их конфиги): сначала допиши блок directai-mcp, сделай копию конфига
харнеса (`*.bak`).

## 7. После успеха — удали свои бэкапы

Завершилось успехом и проверкой из §5 — удали созданные тобой бэкапы
(`*.bak-*`, `*-tool-backup-*`, копии конфигов). Чужие файлы не трогай.

Правила записи (бюджеты/стратегию не менять, guard не выключать,
запись только через план с подтверждением) — `README.md §1.1, §5–6`.
