# DirectAI MCP — публичный обзор

Локальный MCP-сервер для чтения статистики и управления Яндекс Директом.
Работает на вашем компьютере, в интернет ничего не выставляет.

- Чтение: статистика (кампании, группы, объявления, фразы, запросы, регионы,
  площадки, устройства, аудитории, сравнения периодов), настройки кампаний,
  ставки, корректировки, модерация, Яндекс.Вебмастер (сайты, ИКС,
  диагностика, поисковые запросы), ретаргетинг и аудитории кабинета.
- Отчёты Метрики (v1.12.0): визиты, отказы, цели и CR по источникам
  (`metrika_traffic`, `metrika_goals_report`, `metrika_bytime`) и связка с
  Директом по кампаниям — расход/клики + визиты/цели, CPA и проверка
  «клики → визиты» (`metrika_direct_cpa`). Цели и названия — из целей
  счётчика Метрики; `goals.toml` — названия и запасной тип.
- Цели Метрики (v1.17.0): создание, изменение и удаление целей счётчика
  (`metrika_goal_create`, `metrika_goal_update`, `metrika_goal_delete`) —
  Management API, нужен отдельный OAuth-токен приложения Метрики с правом
  `metrika:write`. Типы целей и условия — как в API Метрики; удаление
  необратимо и требует подтверждения владельца.
- Токен Метрики (v1.17.1) отдельный: `directai-mcp set-metrika-token --login
  <логин>`, хранится в Credential Manager под своим ключом. Без него чтение
  Метрики работает на токене Директа с примечанием, запись целей недоступна.
- Прогноз без записи: ставки и цена по существующим фразам
  (`keyword_bids_forecast`), спрос и цены для новых фраз до их добавления
  (`phrases_forecast`). Прогноз Яндекса — не гарантия.
- Wordstat через Yandex Cloud Search API v2: топ и связанные поисковые
  запросы (`wordstat_top`), динамика частотности (`wordstat_dynamics`),
  региональное распределение (`wordstat_regions`) и справочник регионов
  (`wordstat_regions_tree`). API-ключ хранится в Credential Manager, а
  `folderId` — в пользовательском конфиге.
- Ретаргетинг и Аудитории (v1.10.0): чтение условий и привязок работает
  всегда; **запись выключена по умолчанию** (`[retargeting] write_enabled=false`)
  и включается только явным решением владельца.
- Журнал кампании (v1.13.0): один файл на кампанию — что меняли, заметки
  («почему») и результаты по периодам со снимками (`campaign_journal`,
  `campaign_journal_snapshot`, `campaign_journal_note`). Хранится локально.
- Запись: только через план (`plan_write` → ваше подтверждение → `apply_write`)
  с повторным чтением (read-back) и журналом.
- Guard: бюджеты и смена стратегии (включая ключевые цели и их ценности)
  запрещены везде; замены целиком, пауза
  кампаний/объявлений и удаления — только в тестовых кампаниях `[TEST DirectAI]*`.
  Цели Метрики живут вне Директа: перед записью проверяется право на счётчик
  и отсутствие точного дубля, удаление цели — только после явного
  подтверждения владельца. Текст блокировки — защита, а не ошибка: обход
  не предлагается.
- Деньги — `Decimal` с `HALF_UP`; сравнение периодов — только через `stats_compare`.
- Скиллы-сценарии (`skills/`): `directai-campaign-audit` (разбор кампании →
  план улучшений, только чтение) и `directai-campaign-create` (создание
  кампании из брифа, запись через планы).

## Правила для агентов-клиентов MCP

- Почасового среза в Reports API нет: часы запрашиваются только через
  `group_by=weekday` (свод по дням недели). `Hour/DayOfWeek` не запрашивать
  и не эмулировать вручную.
- Журнал операций и журнал кампании содержат только операции DirectAI
  (`plan_write`/`apply_write`): причины ручных изменений в кабинете по ним не
  выясняются — для ручных правок используйте `changes_check`.
- Перед оптимизацией кампании — читать `campaign_journal` (история правок и
  результаты), CPA считать по основной цели; после работы — сохранить
  `campaign_journal_snapshot` за период и заметку `campaign_journal_note`.
- Блокировка guard — это защита, а не ошибка. Агент останавливается и сообщает
  владельцу; конфиг guard не ищет и не меняет; обход защиты не предлагает;
  операцию на другую кампанию без вашего явного указания не переносит.
  Снятие ограничения — только ручным решением владельца.
