# Безопасность записи и Guard

DirectAI меняет рекламу только через план, только с вашего подтверждения
и с повторной проверкой результата. Ниже — как это устроено и что именно
запрещено.

## Как проходит запись

1. ИИ вызывает `plan_write` — сервер показывает предпросмотр «было →
   станет» и предупреждения (например, ставка меняется больше чем в 2 раза).
2. Вы читаете предпросмотр и явно разрешаете.
3. ИИ вызывает `apply_write` (с `acknowledge_warnings=true`, если были
   предупреждения) — сервер выполняет запись, затем **повторно читает
   объект (read-back)** и пишет всё в журнал.

Итоговые статусы:

| Статус | Что значит |
|---|---|
| `applied` | запись подтверждена read-back |
| `partial` | часть строк отклонена API |
| `failed` | запись не выполнена |
| `unverified` | результат неясен (таймаут, обрыв) — проверить вручную |

`unverified` не повторяется вслепую: сначала перечитывается объект.

Планы лежат в каталоге `plans\` и общие для всех процессов сервера.
План, созданный в одном процессе, применяется из любого другого ровно
один раз: повтор — «уже применён», истёкший — «просрочен», неизвестный
id — «не найден». TTL плана — 15 минут, просроченные чистятся
автоматически. Прямых записей в обход плана не бывает.

Журнал: инструмент `get_operation_log` (последние операции, можно
фильтровать по кампании) и файл `journal.sqlite`. В журнал попадают только
операции DirectAI; ручные правки в кабинете видны через `changes_check`.

## Guard: два режима

Guard включён по умолчанию: `[guard] guard = true` в `accounts.toml`
плюс дефолт в коде. Перед каждой записью он сверяет **живое имя
кампании** через API.

```toml
[guard]
guard = true
mode = "confirm"   # по умолчанию "block"
```

Два режима отличаются только судьбой **политических запретов**.
Жёсткие ограничения (см. ниже) действуют одинаково в обоих режимах.

| Что за операция | `block` | `confirm` |
|---|---|---|
| Обычные боевые правки: фразы (добавление, пауза/запуск), объявления (создание, тексты, ссылки), ссылки и уточнения, регионы групп, минус-фразы (добавление), ставки и корректировки (кроме удаления), ExcludedSites (добавление), расписание | разрешено планом | разрешено планом |
| Бюджеты, смена стратегии, ключевые цели и их ценности | блок | опасный план + подтверждение |
| Переименование кампании, модерация, создание боевой кампании | блок | опасный план + подтверждение |
| Пауза, запуск, архив кампаний и объявлений, замены целиком, удаления, правки вне `[TEST DirectAI]*`, удаление корректировок, чужие общие объекты | блок (кроме обычных боевых правок выше) | опасный план + подтверждение |
| Объект не найден, поле `read_only`, Аудитории или ретаргетинг выключены, неизвестное действие, сегмент без префикса | блок | блок |

### `block` — запрет

Политические ограничения — это блокировка до обращения к API:

- бюджеты, смена стратегии и ключевые цели с их ценностями;
- переименование кампании, модерация, создание кампании без префикса
  `[TEST DirectAI]`;
- пауза, запуск, архив кампаний и объявлений, замены целиком, удаления,
  правки вне `[TEST DirectAI]*`, удаление корректировок, чужие общие
  объекты.

Обычные боевые правки при этом разрешены: фразы (добавление,
пауза/запуск), объявления (создание, тексты, ссылки), ссылки и уточнения,
регионы групп, минус-фразы (добавление), ставки и корректировки
(кроме удаления), ExcludedSites (добавление), расписание. Правка набора
минус-фраз кампании и пауза объявлений сюда не входят — это политические
операции из таблицы выше.

### `confirm` — опасный план и подтверждение владельца

Политические ограничения не блокируют запись, а превращают план в
**«⚠ ОПАСНАЯ ОПЕРАЦИЯ»** со списком причин:

- бюджет (`daily_budget`, `strategy` с `WeeklySpendLimit`);
- смена стратегии;
- изменение ключевых целей и их ценностей;
- модерация;
- переименование кампании;
- создание кампании без префикса `[TEST DirectAI]`;
- пауза, запуск, архив кампаний и объявлений;
- правки вне `[TEST DirectAI]*`;
- замены целиком;
- удаление корректировок;
- чужие общие объекты.

Такой план применяется только `apply_write(..., owner_confirmed=true)` —
агент ставит флаг **лишь после явного «да» владельца в чате на этот
конкретный план**. Согласие на один план не переносится на другой
и на пересобранный план. Предупреждения по-прежнему требуют отдельно
`acknowledge_warnings=true`. В журнал операция пишется с пометкой
`[ОПАСНАЯ, подтверждено владельцем]`.

### Что остаётся жёстким в обоих режимах

- объект не найден или ошибка API;
- поля `read_only` (реестр `campaign_setting_notices`);
- выключенные Аудитории и ретаргетинг (`write_enabled=false`);
- сегмент Аудиторий без префикса `[TEST DirectAI]`;
- неизвестные действия.

Guard не ослабляет свойства плана: `plan_id`, TTL 15 минут,
`acknowledge_warnings`, `owner_confirmed`.

## Тестовая кампания

Создайте в интерфейсе Директа кампанию с именем, начинающимся на
`[TEST DirectAI]` (можно черновик). Только в ней доступны замены целиком,
пауза кампаний и объявлений, удаления.

Цели Метрики живут вне Директа, поэтому префикс к ним не относится: перед
записью проверяются право на счётчик, отсутствие дубля и лимит 200 целей
(это отказ до API), а удаление цели в любом режиме guard требует
`owner_confirmed=true`.

## Неуправляемые поля

Реестр [`notices`](../src/directai_mcp/catalog/notices.py) — единый список
настроек, которые нельзя писать. Сейчас там одно поле:

`ENABLE_AREA_OF_INTEREST_TARGETING` — отменено Яндексом 31.08.2026.
Значение `YES`/`NO` только читается и не трактуется как действующий
переключатель. Запись отклоняется до API.

Правило для любого агента: поля из реестра не писать никогда, даже если
API формально их принимает.

## Как выключить Guard

Только вашим решением: поставьте `guard = false` в `accounts.toml`
и убедитесь, что нет переменной `DIRECTAI_TEST_GUARD=1`. После тестов
верните `true`.

Агентам это запрещено: конфиг guard агент не ищет и не меняет, обход
не предлагает.

## Правило для агентов-клиентов MCP

Текст блокировки guard — это **защита, а не ошибка**.

При блокировке агент:

1. останавливается и сообщает вам: какая операция, какой объект, почему
   заблокирована. В режиме `confirm` показывает причины дословно
   и применяет план с `owner_confirmed=true` только после вашего явного
   «да» на этот план;
2. **не ищет и не меняет** конфиг guard (`accounts.toml`, секция `[guard]`,
   переменная `DIRECTAI_TEST_GUARD`) и вообще ничего в `safety/`;
3. **не предлагает обход** защиты;
4. **не переносит** операцию на другую кампанию (в том числе тестовую)
   без вашего явного указания.

Ни один инструмент сервера конфиг guard не пишет и не читает наружу:
единственный источник — `accounts.toml` и переменная окружения.

## Сравнение периодов и выбор инструмента

1. Сравнение периодов агент выполняет только через `stats_compare`
   (A, B, Δ абсолютная, Δ% одним вызовом). Два вызова `stats_*`
   с ручной арифметикой запрещены — они дают разную точность Δ%.
2. Если вы указали конкретный MCP-сервер или инструмент, агент использует
   только его и не подменяет другим.

## Токены и секреты

- Токен Директа хранится только в Credential Manager (`directai-mcp`) или
  в переменной `DIRECTAI_TOKEN`. В файлах и репозитории его нет никогда.
- Токен Метрики — отдельный ключ Credential Manager
  (`directai-mcp-metrika`) или `DIRECTAI_METRIKA_TOKEN`.
- Токен Вебмастера — `directai-mcp-webmaster` или
  `DIRECTAI_WEBMASTER_TOKEN`; ключ Wordstat —
  `directai-mcp-wordstat` или `DIRECTAI_WORDSTAT_API_KEY`.
- Ввод токена — только скрытым полем команды (`directai-mcp set-token`,
  `set-metrika-token`, `set-token --wordstat`) в терминале владельца.
  В чат, аргументы командной строки и файлы репозитория токен не передаётся.
  Если токен попал в чат — отзовите его в Яндекс ID и выпустите новый.
- Токены передаются только заголовками (`Authorization: OAuth` / `Bearer` /
  `Api-Key`) и не попадают в URL, ответы инструментов, журнал операций
  и предпросмотр плана.

### Секреты в логах

- Логи HTTP-клиентов (`httpx`, `httpcore`) всегда на уровне **WARNING**:
  на INFO логгер пишет URL запроса целиком, а значит и query-параметры.
  Поднимать их уровень нельзя.
- Все обработчики логов чистят значения параметров `oauth_token`, `token`,
  `apikey`, `api_key`, `access_token`, `refresh_token` → `***`. Тексты
  сетевых ошибок Метрики чистятся тоже.
- Файл лога: `%USERPROFILE%\.directai\logs\directai.log`. Если секрет туда
  попал (например, старая версия): перевыпустите токен и удалите файл —
  он пересоздаётся при следующем запуске.

```powershell
Remove-Item "$env:USERPROFILE\.directai\logs\directai.log"
```

## Ограничения записи по типам объектов

- Бюджеты и стратегия: в `block` — блок, в `confirm` — опасный план
  с подтверждением владельца. Безопасного «тихого» изменения не бывает.
- Ключевые цели — класс «стратегии»: в `block` запрещены, в `confirm` —
  опасная операция (см. [actions.md](actions.md#ключевые-цели-campaigns_update-priority_goals)).
- Расписание — обычная настройка, разрешена в обоих режимах.
- Аудитории и ретаргетинг — только при явном `write_enabled = true`
  в `accounts.toml`; имена сегментов Аудиторий — только
  `[TEST DirectAI]*`.
- Пакетная стратегия: ключевые цели нельзя передавать привязанной
  кампании — сначала её нужно отвязать вручную.
