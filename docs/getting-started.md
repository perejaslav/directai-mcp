# Установка и первая проверка

Полная процедура: от требований до первого запроса через ИИ-ассистента.
Если вы уже пользуетесь DirectAI, обновление и диагностика —
в [troubleshooting.md](troubleshooting.md).

## Требования

Обязательно:

- Windows 11. Инструкции только для PowerShell; macOS и Linux
  не тестировались и не поддерживаются.
- Аккаунт Яндекс Директа хотя бы с одной кампанией (можно черновик);
  для агентств — главный логин агентства.
- Своё приложение на oauth.yandex.ru (анкета на 5 минут, права Директ
  и Метрика) — запомните ID приложения.
- Одобренный доступ к API Директа (Инструменты → API → заявка с ID
  приложения). Одобрение занимает до нескольких дней.
- ИИ-помощник с поддержкой MCP: OpenCode, Codex, Claude Code,
  Claude Desktop, Hermes.

Желательно: доступ к счётчику Метрики — иначе выручка из CRM
не отличается от условной ценности целей.

Не нужно: программировать, покупать сервер, заранее ставить git или Python.

## Порядок действий

1. Создайте приложение и подайте заявку на доступ к API — это самое
   долгое, начните с этого.
2. Пока ждёте одобрения — установите DirectAI.
3. Когда заявку одобрят — получите токен и выполните проверку
   (`set-token`, затем `check`).

Токен вы вводите сами в своём терминале, никогда не в чат.

## Установка

Нужны `uv` и `git` — оба ставятся через `winget`:

```powershell
winget install --id Git.Git -e --accept-package-agreements --accept-source-agreements
winget install --id astral-sh.uv -e --accept-package-agreements --accept-source-agreements
```

Если после установки команды не найдены, обновите PATH в этой сессии:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")
```

Нет `winget` — поставьте App Installer из Microsoft Store.

Клонирование и установка:

```powershell
cd $env:USERPROFILE
git clone https://github.com/perejaslav/directai-mcp.git directai-mcp
cd $env:USERPROFILE\directai-mcp
uv tool install --editable .
uv tool update-shell
directai-mcp init
```

Первая установка качает Python — это может занять несколько минут,
это не зависание.

Папка `directai-mcp` уже есть — не клонируйте заново, а выполните
`git pull` внутри неё.

## Доступ к API Директа

Если доступ к API ещё не одобрен:

1. Создайте приложение типа «Для доступа к API или отладки»
   на <https://oauth.yandex.ru/client/new> с правами `direct:api`
   и `metrika:read` (плюс `metrika:write`, если планируете менять цели
   счётчика). Redirect URI настраивать не нужно — он фиксирован:
   `https://oauth.yandex.ru/verification_code`.
2. Откройте ссылку, подставив ID приложения:

   ```text
   https://oauth.yandex.ru/authorize?response_type=token&client_id=ID_ПРИЛОЖЕНИЯ&redirect_uri=https://oauth.yandex.ru/verification_code
   ```

3. Нажмите «Разрешить» — токен появится в адресной строке. Копируйте
   только значение после `access_token=` и до `&`
   (вид: `access_token=y0_AgA...&token_type=...`), не весь URL.
4. Подайте заявку на доступ к API в интерфейсе Директа
   (Инструменты → API → Мои заявки). В описании укажите
   «личный учёт статистики и управление своими кампаниями».
   Инструкция Яндекса: <https://yandex.ru/dev/direct/doc/ru/concepts/register>.

Ошибка 58 до одобрения заявки — норма, просто ждём.

## Настройка аккаунтов

`init` создаёт `%USERPROFILE%\.directai\` и копирует примеры конфигов,
не трогая существующие.

Откройте `%USERPROFILE%\.directai\accounts.toml`:

- `[auth] login` — реальный главный логин (владелец токена);
- под каждый логин — свой `[aliases.*]` с коротким именем и ролью;
- демо-алиасы из примера замените полностью;
- `goals.toml` необязателен: названия целей Метрики можно заполнить позже.

Секретов в `accounts.toml` нет.

## Токен Директа

```powershell
directai-mcp set-token --login ВАШ_ЛОГИН
```

Команда маскированно спрашивает токен и кладёт его в Credential Manager
Windows. Символы не отображаются — это нормально: вставьте и нажмите Enter.
В файлах токена нет никогда.

Токен в чат передавать запрещено. Если вставили — отзовите его в Яндекс ID
и выпустите новый.

Альтернатива Credential Manager: переменная `DIRECTAI_TOKEN`.

## Проверка

```powershell
directai-mcp check
```

Ожидание — строки `OK` по каждому аккаунту с числом кампаний и остатком
баллов. Расшифровка ошибок:

| Код | Что значит |
|---|---|
| `53` | неверный токен — повторите `set-token` |
| `58` | нет доступа к API — вернитесь к заявке |
| `513` | у логина нет аккаунта в Директе — создайте кампанию в интерфейсе |
| `152` | кончились баллы API — подождите до завтра |

Полный список кодов: <https://yandex.ru/dev/direct/doc/ref-v5/concepts/errors-list.html>.

Самопроверка сервера (баллы не тратит):

```powershell
directai-mcp probe
```

Ожидание — две строки `OK`: версия сервера, число инструментов
и найденный `stats_summary`. Сырые stdio-пробы вручную не делайте —
только `probe`.

## Подключение к ИИ-агенту

Команда запуска везде одна — `directai-mcp` без аргументов:
это STDIO-сервер. После настройки перезапустите харнес.

OpenCode, файл `%USERPROFILE%\.config\opencode\opencode.json`:

```json
{
  "mcp": {
    "directai-mcp": {
      "type": "local",
      "command": ["directai-mcp"],
      "enabled": true
    }
  }
}
```

Остальные клиенты — Codex, Claude Desktop, Claude Code, Hermes — готовые
блоки в [examples/harness-configs.md](../examples/harness-configs.md).

Если харнес не видит команду, укажите полный путь к exe
(покажет `(Get-Command directai-mcp).Source`), а не путь внутрь
каталога установки `uv`.

Проверка в новой сессии: «Используй только directai-mcp: покажи расходы
по всем аккаунтам за вчера». Цифры должны совпасть с веб-интерфейсом
Директа.

## Файлы в `%USERPROFILE%\.directai\`

| Файл | Что внутри и как править |
|---|---|
| `accounts.toml` | Кабинеты: `[auth] login`, `[aliases.*]`, `defaults` (`include_vat`, `max_rows`, `attribution`), секции `[guard]`, `[audience]`, `[retargeting]`, `[metrika]`, `[wordstat]`. Секретов нет. Применяется со следующего запроса |
| `rules.toml` | Правила: обязательный DisplayUrlPath, слова для заголовков, пороги `max_budget_ratio` и `max_bid_ratio` (предупреждения при резких изменениях) |
| `goals.toml` | `id цели → Название`. В отчётах цель видна как «Название (id)» |
| `journal.sqlite` | Журнал всех записей (не удаляйте) |
| `plans\` | Планы записи: один файл на план, TTL 15 минут, применение ровно один раз |
| `exports\` | CSV/MD-выгрузки из отчётов |
| `logs\` | Логи сервера |

Каталог переопределяется переменной `DIRECTAI_HOME`.

## Дополнительные токены

Все токены хранятся только в Credential Manager (или в переменной
окружения) и вводятся скрытым полем.

| Что | Команда | Ключ Credential Manager |
|---|---|---|
| Метрика (чтение и запись целей) | `directai-mcp set-metrika-token --login ВАШ_ЛОГИН` | `directai-mcp-metrika` |
| Вебмастер | `directai-mcp set-token --webmaster` | `directai-mcp-webmaster` |
| Аудитории (экспериментально) | `directai-mcp set-token --audience` | `directai-mcp-audience` |
| Wordstat (Yandex Cloud) | `directai-mcp set-token --wordstat` | `directai-mcp-wordstat` |

Для Wordstat команда спрашивает `folderId` каталога AI Studio и хранит его
в `[wordstat] folder_id` в `accounts.toml`. Ключ в файл не записывается.
Действия Wordstat только читают и не используют OAuth-токен Директа.

Без отдельного токена Вебмастера используется основной токен.
Без токена Метрики чтение идёт токеном Директа с примечанием в ответе,
а запись целей недоступна.

### Отдельный токен Метрики

Метрика работает на отдельном токене: у приложений «для авторизации
пользователей» лимит 3 группы разрешений, поэтому `metrika:read`
и `metrika:write` живут в своём приложении Яндекс OAuth и в своём ключе
Credential Manager.

Поведение:

- **чтение** Метрики идёт отдельным токеном, если он есть;
- **без отдельного токена** чтение работает на токене Директа, в ответе
  появляется примечание;
- **запись целей** без отдельного токена не начинается — отказ до API.

Выпуск (шаги выполняет владелец, токен в чат не передаётся):

1. В приложении Метрики включите права «Яндекс Метрика» → чтение
   и изменение (`metrika:read` + `metrika:write`), Redirect URI
   `https://oauth.yandex.ru/verification_code` — как у приложения Директа.
2. Выполните команду — она напечатает ссылку с `client_id` приложения
   Метрики:

   ```powershell
   directai-mcp set-metrika-token --login ВАШ_ЛОГИН
   ```

3. Разрешите доступ, скопируйте токен из адресной строки и вставьте
   в скрытое поле. Client secret приложения DirectAI не знает и не хранит:
   OAuth-поток проходит в браузере.
4. Проверка: `directai-mcp check` (строка «Метрика: …») и
   `directai-mcp doctor` (проверка `l. Метрика`). Строка «Метрика: …»
   есть и в `describe_action` без аргументов.

Что показывают проверки (значение токена не печатается нигде):

- источник токена и его длину;
- `client_id` приложения, выпустившего токен (`login.yandex.ru/info`) —
  так видно, что Метрике достался именно токен приложения Метрики;
  если приложение чужое, `check` и `doctor` предупредят;
- читается ли список счётчиков;
- право `metrika:write` **не проверяется**: Яндекс не отдаёт scopes,
  выяснить его можно только записью цели. В выводе честно сказано,
  что право подтвердит первая запись (при 403 сервер объяснит,
  как перевыпустить токен).

Отозвать токен — в Яндекс ID (правки приложения → «Отозвать токены»);
новый выпускается той же командой.

## Установка через ИИ-агента: промпт для новичка

Новичок (свой аккаунт Директа, ничего общего с автором) копирует блок
ниже в любого агента (OpenCode, Codex, Claude Code) — агент поставит всё
с нуля.

Правила: бюджеты и стратегию без «да» владельца не менять; guard не выключать никогда;
